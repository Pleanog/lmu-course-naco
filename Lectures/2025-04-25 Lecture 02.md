## Introduction to Cellular Automata

Cellular automata (CAs) are a class of discrete computational systems that evolve over time based on a set of local rules. Each "cell" in a CA exists in a grid (typically one- or two-dimensional) and has a **finite set of states**. The system's evolution is determined by the **state of neighboring cells**.

This concept is central to **Natural Computing**, as it embodies how **complex behaviors can emerge from simple local interactions**.

> [!CITE] Wolfram – _A New Kind of Science_  
> “Even extremely simple rules can produce behavior of great complexity.”

---

## What is an Automaton?

An automaton is a **finite-state machine** — it consists of:
- A set of **states**.
- A set of **transitions** (rules for moving between states).
- An **initial state** and potentially a set of final or accepting states.

In Cellular Automata, this concept is simplified to a **cell** whose behavior is governed by its state and that of its neighbors.

> [!TLDR] Cellular Automaton
> They are simple automaton applied to each cell with neighborhood-based transition rules.

---

## Structure of Cellular Automata

Each cell:
- Has a **current state** (e.g. on/off, black/white, 0/1).
- Checks the **states of its neighbors** (e.g. left/right in 1D).
- Updates its state according to a **transition function** (rule).

The system evolves synchronously: **all cells update at the same time** based on their current configuration.

## Neighborhoods and Rules

The **neighborhood** defines which cells influence the transition.

For example, a **1D CA** might use:
- Left neighbor
- The cell itself
- Right neighbor


![[Pasted image 20250714205853.png]]

A cellular automaton is formally defined as a tuple

$(G,f,x_0​).$

- G=(V,E) represents a graph with vertices V and edges E⊆V×V.
- A "neighborhood" function
    `neighborhood: V → V^(d+1)` is introduced, which returns an ordered vector of neighbors for a given node `v`, always including `v` itself, where `d` is the neighborhood degree.
- A "state"
    x​∈X is a mapping of vertices to the values {0,1}, with the state space X defined as X=(V→{0,1}).
- The evolution of a state
    xt​ at time step t∈N to its subsequent state xt+1​ is deterministic, governed by a function f:{0,1}d+1→{0,1}.
- The update rule is given by
    xt+1​(v)=f(xt​(u1​),...,xt​(ud+1​)), where $\vec{u}=\langle u_{1},...,u}_{d+1}\rangle=neighborhood(v)$.
- x0​∈X is the initial state.

The rule set (`f`) maps every possible neighborhood configuration to a new state:
- There are 8 possible binary configurations (000 to 111)
- Each rule (like Rule 90) defines an output for each one.

> [!TIP] Elementary Cellular Automata  
> There are 2^8 = 256 possible elementary rules for 1D CAs with binary states and three-cell neighborhoods.

## Interpretation: Local vs. Global Computation


> [!CITE] Lecture Quote  
> "Is local information sufficient for meaningful computation?"

Answer: **Yes, but with limitations**.
When only **local communication** is allowed:
- Aggregation tasks (like finding an average) still work reasonably well.
- Finding extremes or modes is harder and **takes more time**.

> [!question] _Why is local computation more “robust” or “physical”?_  
> Because it mimics real-world systems (like biological organisms or decentralized systems) where only **local sensing and action** is possible. It reduces reliance on a centralized controller and improves **fault tolerance**.

> [!example] Klausurrelevant: Explain the trade-off between global and local computation  
> Local computation is more **scalable and robust**, but limited in **efficiency and accuracy** for global tasks. Algorithms must be carefully designed to overcome this, often using **emergent behavior**.

## Summary Table: Properties of Local Computation

|Aspect|Global Information|Local Information|
|---|---|---|
|Communication Range|Everyone sees everything|Only neighbors can communicate|
|Accuracy (for averages)|High|Moderate|
